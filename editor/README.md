# editor — редактор карт

Инструмент рисования местности под текущий масштаб проекта. Сами карты и сценарии живут в
`maps/` и `scenarios/`, здесь только код.

```bash
py -3.12 editor/map_editor.py                     # стартовый экран
py -3.12 editor/map_editor.py platoon_crop_3      # сразу открыть карту из maps/
```

Команды даны в проектной версии, но самому редактору хватает любого Python 3.9+ с `numpy`,
`Pillow` и `tkinter` — обучающих зависимостей он не тянет. Запускать из КОРНЯ проекта
(`E:\Wargame-RL`), не из `editor/`.

## Файлы

| файл | что |
|---|---|
| `map_editor.py` | приложение: стартовый экран, холст, слои, точки, сохранение |
| `project.py` | параметры проекта — масштаб, размер сетки, состав сторон, палитра |
| `measure.py` | мерка карты (видимость, доли, вердикт годности) |
| `check_gui.py` | дымовой прогон всего пути без открытия окна |
| `check_measure.py` | контроль мерки на отобранном пуле |

## Работа

Холста при запуске нет: **Создать новую карту** (размер задаётся явно, кнопка «под текущий
масштаб» ставит 85 × 85 по 30 м = 2550 м и проверяет совпадение с ареной) либо **Открыть
карту** — списком из `maps/` или через диалог. Размер не косметика: карта под другой масштаб
покроет лишь угол поля, и об этом пишут и стартовый экран, и панель замера.

**Вид.** Колесо — зум к курсору, средняя кнопка или пробел — тащить, ползунок и кнопки
«↺ 90° / ↻ 90°» — поворот на любой угол. Вид крутится независимо от сетки: обводить удобно,
когда снимок лежит ровно, а не когда его угол совпал с осями карты. Отдельно есть поворот
самой сетки на 90° — это уже правка карты, и точки после неё сбрасываются.

**Слои** — как в фотошопе, но клетками. Два вида:

- **слой местности** — та же сетка, но у клетки есть состояние «пусто»: сквозь него виден слой
  ниже. Лес, дороги и застройку можно держать порознь, гасить и переставлять;
- **подложка** — картинка со своей прозрачностью, свободным поворотом, масштабом и
  перетаскиванием мышью (галка «двигать мышью»). В карту не попадает: это опора для обводки.

Операции: видимость, прозрачность, замок, порядок, активный слой, переименование (или двойной
щелчок по списку), дублирование, удаление, «объединить вниз», «свести всё». Рисование идёт в
выбранный слой; если он подложка, скрыт или под замком — редактор откажет и скажет почему,
а не будет молча рисовать в никуда.

**Карта для игры — это сведённая стопка: то, что видно.** Скрытый слой в `maps/<имя>.npy` не
попадает, и строка состояния об этом предупреждает при сохранении. Сама стопка ложится рядом в
`maps/<имя>.editor.npz` (сетки) и в `maps/<имя>.json` под ключом `editor` (имена, прозрачности,
трансформации подложек, точки) — открыл карту, стопка на месте. У карты без этих файлов
(например, у вырезки) стопка собирается из одного слоя.

**Рисование.** Кисть с радиусом, линия, прямоугольник, заливка; ПКМ — ластик, стирает в «пусто»
и открывает слой ниже. Заливка берёт область по видимой карте, а пишет в активный слой.
Отмена/возврат работают и по стопке целиком. Зеркалирование по Y — та же операция, которой
`test_mirror.py` проверяет симметрию среды: нарисовал половину, отразил, и разница в исходе боя
точно не от карты.

**Точки.** Инструмент «точка» ставит объекты захвата и позиции сторон: ЛКМ — поставить или
перетащить, ПКМ — убрать. Позиций на сторону ровно столько, сколько слотов в составе из
`units.json` (сейчас 4), лишние не ставятся. Кнопка «сохранить сценарий» пишет
`scenarios/*.json` в формате `scenario.py` — координаты в игровых единицах `0..ARENA`, среда
таким файлом переопределяет и расстановку, и рубежи. Точки заодно хранятся в `maps/<имя>.json`
под ключом `editor` (среда его не читает), поэтому переживают закрытие карты.

**Замер.** Меряется сведённая карта, пересчёт после каждой правки: доли типов, строения и габарит,
**видимость на 300–900 м** настоящим `terrain.blocked()` на `TerrainMap`, собранной как в
`reset()`, и вердикт **годна / вырождена** по фильтру `maps/crop_platoon.usable()` плюс окно
видимости 25–85 %.

Сохранение карты пишет в `maps/` пару `.npy` (сетка `(Gx, Gy)` int8) + `.json` (`cell_m`,
`building_capacity`) — тот же формат, что читает среда.

## Проверки

```bash
py -3.12 editor/check_gui.py        # весь путь: старт → рисование → подложка → точки → сценарий
py -3.12 editor/check_measure.py    # мерка против отбора пула
```

`check_gui.py` проходит путь целиком без mainloop и проверяет то, на чём легко ошибиться:
сведение стопки (верхний перекрывает нижний, «пусто» пропускает, скрытый слой не идёт в карту),
запрет правки скрытого и запертого слоя, объединение и сведение без изменения вида, отмену по
всей стопке, круг «сохранил — прочитал обратно», обратимость экран↔мир при повёрнутом виде,
зум без увода точки из-под курсора, ось Y (низ экрана — малый Y, свои внизу поля), лимит
позиций по составу, чтение карты игровым `terrain.from_grid` и прохождение сценария через
`scenario.validate()`.

`check_measure.py` — контроль самой мерки. Сейчас все 17 карт пула попадают в окно
(27–81 %, медиана 61 %), обе карты сплошного леса отсеиваются (7 %), расходится одна:
`platoon_crop_8` даёт здесь 29 % против 22 % в исходном отборе. То есть мерка читает на
несколько пунктов выше и у границы окна с отбором расходится — кода того замера в
репозитории нет, это реализация критерия по описанию из `docs/JOURNAL.md`. Для
«годна/вырождена» этого хватает, для сравнения с числами журнала — нет.
