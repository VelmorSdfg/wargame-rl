# Архитектура командования

Целевая схема: **RL играет за ротного командира, правила исполняют**. Документ фиксирует, где
проходит граница, каким словарём отдаются приказы и в каком порядке это строится.

Сложился в обсуждении 2026-08-13. Числа, где они есть, — замеренные, не прикидочные.
Смежные документы: `WARGAME_MECHANICS.md` (механики боя).

---

## 1. Масштаб

Нормативы (советские/российские, натовские близки):

| | Оборона | Наступление |
|---|---|---|
| Рота | до 1.5 км фронт, 1 км глубина | 400–600 м |
| Батальон | 3–5 км (растянуто до 7.5) | 800–1000 м |

Наша вырезка — **7×7 км, то есть батальонный участок**. Для роты по классике вчетверо широко.

**Но ужимать карту нельзя.** Доля поля, которую перекрывает оружие:

```
                1.5 км    3.0 км    7.0 км
винтовка           33%       16%        7%
пулемёт            70%       35%       15%
автопушка         121%       61%       26%
пушка ОБТ         149%       75%       32%
ПТУР              159%       79%       34%
```

На «уставных» 1.5 км ПТУР перекрывает 159% карты — всё простреливает всё из любой точки,
манёвра нет, игра вырождается. На 7 км получается нужный разброс: пехота обязана сближаться,
ПТУР господствуют на открытом.

**Вывод: 7 км — правильный размер под наши (реалистичные) дальности. Масштабировать надо силы,
а не карту.** «Рота на батальонном фронте» — это ещё и то, что реально происходит в современной
войне при низкой плотности войск.

## 2. Состав

Целевой (юнит = отделение или машина):

```
1-й мсв : 3 отделения + 3 БМП
2-й мсв : 3 отделения + 3 БМП
3-й мсв : 3 отделения + 3 БМП
танковый взвод : 3 ОБТ
ПТУР           : 2-3 расчёта
                        ~23-24 юнита, ПЯТЬ единиц управления
```

Текущий состав (10 юнитов: 5 пех / 2 БМП / 1 ОБТ / 2 ПТУР) на взводы не делится — это
усиленный взвод, а не рота. Разворачивать в полную роту **после** того, как заработает
командование элементами на нынешних десяти (иначе меняем два больших параметра разом).

**Состав должен жить в данных, а не в коде.** Целевой вид `units.json`:

```json
"order_of_battle": [
  {"name": "1-й мсв",  "units": ["infantry","infantry","infantry","ifv"], "vocab": "infantry"},
  {"name": "танковый", "units": ["mbt","mbt","mbt"],                      "vocab": "armor"},
  {"name": "ПТУР",     "units": ["at_infantry","at_infantry"],            "vocab": "at"}
]
```

Число голов политики, размер наблюдения и словарь выводятся отсюда. Плюс потолок с добивкой
и маскированием (до ~6 элементов / ~24 юнитов), чтобы одна модель работала с разными составами.

## 3. Граница: правила против RL

**Принцип: если правильный ответ можно записать — записывай правилом. Если хороший ответ
узнаётся только по последствиям — учи моделью.**

| Слой | Кто | Что |
|---|---|---|
| 0. Симуляция | правила | пробитие, подавление, LOS, местность. Не решение вообще |
| 1. Отделение, экипаж | правила | дойти (A*), укрытие, дорога, здание, выбор цели стволу |
| 2. Взвод | правила | строй, взаимное прикрытие, перекаты. Уставные шаблоны — записываются |
| 3. **Ротный** | **RL** | задача, объект, направление. Основной мозг |
| 4. Усиление | **RL, медленный** | что кому придано, главное направление. Редкие решения |
| 5. Оперативный (25 км) | — | другая игра, не расширение этой |

**Главная опасность: каждое решение, принятое правилами, — это решение, которого агент принять
не может.** Потолок системы = качество правил + выразительность словаря. Пример уже допущенной
ошибки: `ADVANCE` шёл к БЛИЖАЙШЕЙ зоне, то есть правило отняло у агента выбор объекта.

Правила **распознают** обстановку, модель **выбирает** ответ. Прописывать «если ПТУР на гребне —
обходить справа» нельзя: это опять отнимает решение.

## 4. Словарь приказов

Три головы на элемент. Недопустимые сочетания снимаются маскированием.

```
задача (9)     : ОВЛАДЕТЬ · ОБОЙТИ · ЗАКРЕПИТЬСЯ · ПРИКРЫТЬ · ПОДДЕРЖАТЬ
                 СКОВАТЬ · ПОДАВИТЬ · ОТОЙТИ · РЕЗЕРВ
объект (до 8)  : объект местности 1..3 | СВОЙ элемент 1..5 | элемент противника
направление (3): слева · фронтально · справа
```

Голова «объект» **полиморфна** — смысл зависит от задачи:

| Задача | Объект | Что делает исполнитель |
|---|---|---|
| `ОВЛАДЕТЬ` | объект местности | выдвинуться прямо, занять, удерживать |
| `ОБОЙТИ` | объект местности | то же, но скрытно, вне зон вражеского огня — дольше |
| `ЗАКРЕПИТЬСЯ` | — | стоять, занять укрытия, вести огонь |
| `ПРИКРЫТЬ` | **свой элемент** | занять позицию с линией огня на его направление, держать |
| `ПОДДЕРЖАТЬ` | **свой элемент** | двигаться следом эшелонированно, в готовности вступить |
| `СКОВАТЬ` | элемент противника | держать под угрозой с предельной дистанции, в бой не ввязываться |
| `ПОДАВИТЬ` | элемент противника | выйти на дальность и вести огонь |
| `ОТОЙТИ` | — | выйти из-под огня к своему краю |
| `РЕЗЕРВ` | — | держаться позади |

Читается как боевой приказ: **«ПТУР — прикрыть 2-й мсв, справа»**, **«1-й мсв — овладеть
объектом 3, обход слева»**.

**`ПРИКРЫТЬ` — важнейшая из добавляемых задач**: это первая, которая СВЯЗЫВАЕТ элементы между
собой. Без неё агент не может задумать ничего сложнее «все побежали на объект»; с ней появляется
сам класс замыслов (один сковывает — другой маневрирует), ради которого всё строится.

### Направление задаётся относительно, не по ориентирам

Замер: на вырезку приходится **~40 именованных ориентиров** (посёлки, узлы дорог, рощи;
разброс 27..52). Слишком много для словаря, и они разные на каждой из 20 карт — агент не обобщит.

Поэтому `слева / фронтально / справа` считается относительно линии «элемент → объект».
Всегда определено, не зависит от карты.

**Позиции при этом всё равно получаются осмысленными**: «прикрыть 2-й мсв справа» → правила
сканируют правый фланг и выбирают лучшую огневую позицию, а ей окажется лесополоса или окраина
посёлка — потому что там укрытие и обзор. Командир указывает рубеж и направление, а не куст.

### Размер пространства действий

```
сейчас, по юнитам           : 5¹⁰  ≈ 9 800 000
по элементам (5 × 11)       : 11⁵  ≈   161 000
полная рота по юнитам       : 5²⁴  — невозможно в принципе
```

На ротном масштабе командование элементами — не улучшение, а единственный работающий вариант.
Это же приём («композиция действий»), который в Gym-µRTS назвали обязательным.

### Темп отдачи приказов

Сейчас приказ держится 4 физических шага (`ACTION_REPEAT`). Для ротного слишком часто.
Ориентир — **8–16 шагов**: замысел успевает реализоваться, ~30 решений за эпизод вместо ~100,
назначение заслуг сильно проще. Подбирать замером.

## 5. Наблюдение и сеть

**Сейчас `MlpPolicy` на плоском векторе — это леса, а не здание.** Юнит `k` занимает
фиксированный кусок вектора, у каждого слота свои веса: правило «раненый под огнём на открытом —
в беде» выучивается заново для каждого из 20 (а в роте — 48) слотов.

**Целевое — общий кодировщик юнита:**

```
плоский первый слой (48 юнитов): 816 × 256 = 208 896 весов, обучаются раздельно
общий кодировщик               :  17 ×  64 =   1 088 весов, обучаются на ВСЕХ 48 юнитах

юниты -> кодировщик -> эмбеддинги
        свернуть внутри элемента -> состояние взвода
        свернуть по всем         -> общая обстановка
голова элемента: f(своё состояние, общая обстановка) -> приказ
```

Даёт обобщение, безразличие к порядку слотов и **работу с переменным составом** без переучивания.
Дальше внимание заменяет равномерное усреднение обученной оценкой значимости (как в AlphaStar).
В SB3 это `features_extractor_class`, ~50 строк.

**Тактические признаки в наблюдение** (считаются правилами, подаются готовыми): соотношение сил
общее и по элементам, статус каждого объекта, угроза на элемент (сколько стволов достаёт),
подавление, есть ли у ПТУР линия огня с текущей позиции. Дёшево считать, превращает набор
координат в обстановку.

## 6. Порядок работ

1. **Приказы элементам** на текущих 10 юнитах, 3 элемента по типу (деление уже есть в
   `_role_move`), обычный MLP. Проверка гипотезы: учится или нет.
2. **Тактические признаки** в наблюдение.
3. **Маскирование** недопустимых приказов и пустых слотов.
4. **`ПРИКРЫТЬ`** — первая связывающая задача.
5. **`ОБОЙТИ`** — карта стоимости с учётом вражеских секторов обстрела.
6. Общий **кодировщик юнита**, затем внимание.
7. Разворот в **полную роту**, состав из данных.
8. Усиление отдельным медленным решением.

**Не делать раньше времени:** A* (замерено — исполнение приказа `ADVANCE` доходит в 93.8%
случаев, застревает 1.0%, не узкое место), self-play (в µRTS недоработал; сильный скриптовый бот
оказался лучше), туман войны, отдельные модели под рода войск.

**Правило:** менять по одной вещи за заход. Иначе при плохом результате виноватого не найти —
на этом уже обжигались.
