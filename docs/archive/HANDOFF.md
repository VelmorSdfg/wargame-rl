# WarGame — мини-варгейм для RL (передача в новый чат)

Этот документ — самодостаточный брифинг. Прочитав его, можно продолжать проект
без контекста прошлого чата.

## Что это и зачем
Мини-тактический варгейм в непрерывном 2D-пространстве (в духе WARNO, но headless и
сильно упрощённо), написанный как **среда для обучения с подкреплением (RL)**.
Идея: агент-командир управляет отрядом из 4 юнитов против скриптового бота и должен
освоить **комбинирование родов войск** (камень-ножницы-бумага + прикрытие), а не
«толпой в лоб». Наблюдение — вектор чисел → PPO с `MlpPolicy` (Stable-Baselines3).

Долгосрочная цель — довести до **self-play** (враг = копия агента), потом добавить
туман войны/разведку и рельеф (см. «Дорожную карту»).

## Механика боя
- Непрерывное поле 100×100 (`ARENA`), эпизод до 400 шагов (`MAX_STEPS`).
- Полная видимость (тумана войны пока НЕТ).
- Каждый шаг: свои двигаются по приказу агента, враги по скрипту, затем все стреляют
  одновременно по ближайшей достижимой цели в радиусе. Урон и подавление применяются разом.
- **Пробитие брони (субтрактивное, Red Dragon):** `pen < armor` → рикошет 0; на кромке ×0.5;
  за каждый пункт оверматча растёт (кап ×1.4). HP маленькие → бой смертельный (ПТУР сносит ОБТ
  за 2 выстрела, ОБТ ваншотит лёгкую технику). По пехоте — множитель `soft` оружия: тяжёлые
  стволы (пушка/автопушка) `soft` низкий (снаряд бьёт по отряду 10 чел ~3 бойцов/выстрел), а
  стрелковка/пулемёт `soft` 1.0.
- **Множитель по мягким целям (`soft`):** урон по НЕбронированным. У ПТУРа `soft=0.25`
  (ракета плоха по пехоте), у остальных 1.0.
- **Мёртвая зона (`minrng`):** у ПТУРа 9 м — вблизи не стреляет (расчёт беспомощен).
- **Подавление/мораль:** под огнём растёт `suppr` (спадает со временем); снижает точность
  и скорость; при `suppr >= 1.0` юнит «прижат» и не стреляет.
- **Перезарядка (`cd`):** у каждого СТВОЛА счётчик `reload` тикает вниз каждый шаг; стреляет
  только когда `reload == 0`, после выстрела `reload = cd` (расходуется даже при промахе).
  Делает удары «чанковыми» и создаёт окно уязвимости между выстрелами.
- **Местность (`terrain.py`):** сетка тайлов (клетка 2 м), генерится каждый reset. Лес/здание дают
  `cover` (урон и подавление по цели × (1−cover)) и замедляют движение (`speed`). **Линия огня:**
  здание — глухая стена; лес перекрывает выстрел, только если луч идёт сквозь него дольше
  `see_through_m` (6 м) — то есть вплотную в лесу дерутся, а далеко сквозь чащу нет (иначе бой
  вставал намертво, когда стороны сходились в лесу). В obs 7-е число на юнита = «cover подо мной».
- **Гарнизон (посадка в здания):** пешие (`armor==0`: пехота/ПТУР) занимают здания — технике они
  непроходимы (объезжает), **вместимость 1 отряд на здание**. Гарнизон получает cover 0.65 и
  **стреляет наружу** (своё здание прозрачно для его огня). По засевшему может бить любой, кто видит
  дом, но урон режется укрытием: обычное оружие −65% (0.65), **фугас** (`demolish`: пушка ОБТ,
  автопушка БМП) **−50%** и бьёт сквозь стену. Пехота ролево штурмует засевшего врага (заходит внутрь),
  ПТУР прячется в укрытие. Рендер: занятое здание красится в цвет команды (бледно), значок сидящего
  отряда — по центру дома.
- **Мульти-оружие + приоритет целей:** каждый готовый ствол выбирает цель, по которой он
  максимально эффективен (урон = dmg×пробитие), при равенстве — ближайшую; бесполезные цели
  пропускает (пулемёт не бьёт броню, пушка не тратится зря). Флаг оружия `vs_soft:false` (у ПТУР)
  — не стрелять по мягким целям (пехота/ПТУР), беречь ракету для брони; при отсутствии брони молчит.

### Ростер (4 типа на сторону), файл `STATS` в `wargame_env.py`
| Юнит (id) | HP | rng/minrng | dmg | armor | pen | soft | cd | роль |
|---|---|---|---|---|---|---|---|---|
| пехота (`infantry`) | 120 | 16/0 | 9 | 0 | 5 | 1.0 | 1 | гроза пехоты/ПТУР, по броне 0, прикрытие; непрерывный огонь |
| ПТУР (`at_infantry`) | 50 | 34/9 | 90 | 0 | 40 | 0.10 | 6 | истребитель брони издалека; долгая перезарядка, беспомощен по пехоте, хрупкий |
| БМП (`ifv`) | 150 | 22/0 | 30 | 10 | 18 | 1.0 | 2 | быстрый универсал; по ОБТ почти никак |
| ОБТ (`mbt`) | 260 | 28/0 | 75 | 30 | 35 | 1.0 | 3 | таран, бьёт всё |

**`cd` — перезарядка (шагов между выстрелами).** Урон стал «чанковым»: редкий крупный удар +
окно уязвимости на перезарядке (вкус Wargame Red Dragon). Пехота стреляет каждый шаг (cd=1),
ПТУР — раз в 6 шагов.

Урон за ВЫСТРЕЛ (dmg·mult·acc), для интуиции:
```
бьёт →     пехота   ПТУР    БМП    ОБТ
пехота      7.2     7.2     0      0
ПТУР        6.5     6.5    64.8   64.8
БМП        22.5    22.5   22.5    5.6
ОБТ        56.2    56.2   56.2   56.2
```
TTK с учётом cd (шагов): пехота→ПТУР ~7; ПТУР→пехота ~111 (**никак**); ПТУР→БМП ~14, ПТУР→ОБТ ~24;
ОБТ→ОБТ ~14. Одинокий ПТУР против рвущегося ОБТ успевает **2 выстрела** (снимает ~50% танка),
затем ОБТ входит в мёртвую зону 9 м — ПТУР немеет и гибнет.

Заложенная тактика: ПТУР бьёт броню редко-но-страшно, но пехота сминает его за ~7 шагов, а сам
он по пехоте почти бесполезен (soft 0.10) → ПТУР ОБЯЗАТЕЛЬНО прикрывать, стрелять с макс. дистанции.

## Интерфейс RL (в `WarGameEnv`)
- **Наблюдение:** `Box(n·8,)` — по 8 чисел на юнита: x/ARENA, y/ARENA, доля HP, подавление,
  жив (0/1), свой/чужой (0/1), укрытие подо мной, готовность оружия (1=все стволы заряжены).
  Число юнитов = 2·len(`FORCE`). Наряд 5 пех/2 БМП/1 ОБТ/2 ПТУР → 20 юнитов → `Box(160,)`.
- **Действие:** `Box(n_side·2,)` = по 2 числа (вектор движения, clip в круг) на каждый свой
  юнит (сейчас `Box(20,)`). Огонь автоматический (не часть действия). ВАЖНО: смена состава в
  units.json меняет форму obs/action → RL надо переобучать.
- **Награда (shaping):** `+0.1·урон врагу − 0.1·урон себе + 50·убитый враг − 30·потеря
  своего`; в конце `+300` победа / `−300` поражение.
- `info`: `friendly_alive`, `enemy_alive`, а на терминальном шаге `win` (bool).

## Как запускать

`approx_kl` держится ~0.03 (стоит `target_kl` от расшатывания).

Показ боя (окно):
```
& "C:\...\Python39\python.exe" play.py models/best_model.zip
```
Демо-GIF без модели:
```
& "C:\...\Python39\python.exe" render_demo.py
```

Визуализация — NATO-символика: свои = синий прямоугольник, враг = красный ромб; значок
внутри: X = пехота, Λ = ПТУР, овал+X = БМП (мех-пехота), залитый овал = ОБТ. Сверху —
HP, тонкие линии — огонь, жёлтое кольцо — подавление.

## Дорожная карта (что делать дальше)
1. **Обучить и оценить** первого командира; GIF обученной модели через тот же рендер;
   посмотреть, освоил ли связки (ПТУР под прикрытием, ОБТ в размен, БМП по флангам).
2. **Self-play:** заменить скриптового бота на копию текущей политики (периодически
   обновляемую) — тогда появляется эмерджентная тактика. Главное — управлять
   нестационарностью (пул прошлых версий противника).
3. **Фаза 2 — туман войны и разведка:** частичная видимость (POMDP) → агенту нужна память
   (рекуррентная политика, напр. `RecurrentPPO` из sb3-contrib). Добавить юнит-разведчик
   (оптика/стелс). ВНИМАНИЕ: туман резко усложняет обучение.
4. **Рельеф/укрытия:** снижение урона в укрытии, блокировка линии видимости.
5. Возможные улучшения ростера: приоритет целей (ПТУР целит в технику, а не в пехоту),
   разное время перезарядки, стоимость юнитов/очки.

## Заметки/грабли (из опыта прошлого чата)
- На Windows PPO использует `SubprocVecEnv` — работает благодаря `if __name__=="__main__"`
  в `train.py`. Если капризничает — можно переключить на `DummyVecEnv`.
- Ctrl+C на Windows часто не прерывает обучение; надёжно — закрыть терминал или
  `taskkill /F /IM python.exe` из другого окна. `best_model.zip` сохраняется по ходу
  (EvalCallback перезаписывает его только при улучшении — на случай, если позднее просядет).
- `target_kl=0.03` в PPO — стоп-кран от расшатывания политики; без него метрики могут
  «улетать» (approx_kl >> 0.1). Не убирать без причины.
- `render_demo.py`/headless-проверки: ставить `SDL_VIDEODRIVER=dummy`, чтобы pygame не
  требовал реальный дисплей.
